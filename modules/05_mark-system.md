# 05. MARK 系统

## 概述

MARK 系统是 SDD 工作流的约束管理机制，用于在长对话中防止关键约束被遗忘。

### MARK 与 Memory 的关系

| 维度     | MARK（CLAUDE.md）      | Memory（Agent 记忆） |
| -------- | ---------------------- | -------------------- |
| 作用域   | 项目级（当前需求）     | Agent 级（跨项目）   |
| 持久化   | 文件持久化             | Agent 系统管理       |
| 可见性   | 团队可见（提交到 git） | 仅当前 Agent 可见    |
| 适用场景 | 项目特有的硬性规则     | 用户通用偏好         |

**判断规则**：

- "这个项目不使用 autoResize" → MARK（项目特有）
- "我习惯用 4 空格缩进" → Memory（通用偏好）
- "changelog 必须记录根因" → MARK（项目规则）
- "回答用中文" → Memory（通用偏好）

---

## MARK 的生命周期

```
触发 → 记录 → 生效 → [固化/废弃]
```

### 1. 触发条件

MARK 只在以下情况创建：

- 用户明确发出硬性规则（"以后不要..."、"必须..."、"禁止..."）
- 用户纠正了 Agent 的行为（"不是这样，应该..."）
- 发现重要约束需要持久化（如 Bug 根因揭示的规则）

### 2. 记录格式

```markdown
### MARK #N: [简短标题]

- 内容：[具体约束描述]
- 来源：[触发场景/对话轮次]
- 状态：生效 | 已固化 | 已废弃
- 关联：[相关的 Bug/DECISIONS 编号，可选]
```

### 3. 编号规则

- 从 #1 开始递增
- 废弃的 MARK 保留编号，不复用
- 新 MARK 使用当前最大编号 + 1

## 防遗漏机制

### 三层防护

```
Layer 1: CLAUDE.md 高频约束区（≤ 5 条）
         → 每次迭代前 Agent 必须回顾
         → 只放最容易被遗忘且影响最大的规则

Layer 2: SPEC.md 头部约束摘要
         → SPEC 顶部的 blockquote
         → 记录与需求强相关的核心约束

Layer 3: 回顾检查点协议（02_workflow.md）
         → 流程强制，不依赖 Agent 记忆
         → 定义"何时必须回顾什么"
```

### 高频约束区规范

CLAUDE.md 顶部的高频约束区：

```markdown
## ⚡ 高频约束（每次迭代必看）

1. SPEC.md 是第一准则，方向调整先改 SPEC
2. 每次迭代必须记录 changelog
3. 所有 agent 文件归属当前 \_dev 目录
4. [项目特定约束 1]
5. [项目特定约束 2]
```

**选入标准**：

- 被违反过至少一次的约束
- 违反后果严重的约束
- 容易在长对话中被遗忘的约束

## MARK 的固化与废弃

### 固化

当一个 MARK 被证明是长期有效的通用规则时，可以固化为：

- **Skill 规则**：提升到 sdd-workflow 的模块中
- **Memory**：如果是跨项目通用的，转为 Agent Memory

固化后，MARK 状态改为"已固化"，并注明去向。

### 废弃

当一个 MARK 不再适用时：

- 状态改为"已废弃"
- 注明废弃原因
- 不删除（保留追溯）

```markdown
### MARK #5: 不使用全局 CSS 变量覆盖 [已废弃]

- 内容：组件样式不使用全局 CSS 变量覆盖
- 来源：Bug 12 根因分析
- 状态：已废弃
- 废弃原因：需求变更，Phase 4 需要支持主题切换
```

## Agent 回顾行为规范

### 回顾时机

参见 [02_workflow.md](02_workflow.md) 的回顾检查点协议。

### 回顾输出格式

```
📋 已回顾 CLAUDE.md（N 条 MARK），本次修改涉及：
- MARK #X：[标题]（[如何遵守]）
- MARK #Y：[标题]（[如何遵守]）
```

### 冲突处理

当 MARK 与当前需求冲突时：

1. 不要静默忽略 MARK
2. 向用户报告冲突
3. 由用户决定：修改 MARK 还是调整需求

---

## 反模式

❌ Agent 自己创建 MARK（必须是用户触发）
❌ MARK 超过 20 条（信息过载，失去防遗漏效果）
❌ 废弃的 MARK 直接删除（失去追溯能力）
❌ 高频约束区超过 5 条（应该只放最关键的）
❌ 回顾时只看不报告（必须输出确认信息）
❌ 遇到冲突时静默忽略 MARK
