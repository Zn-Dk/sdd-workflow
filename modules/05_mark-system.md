# 05. MARK 系统

## 概述

MARK 系统是 SDD 工作流的约束管理机制，用于在长对话中防止关键约束被遗忘。

### MARK 与 Memory 的关系

| 维度 | MARK（CLAUDE.md） | Memory（Agent 记忆） |
|------|-------------------|---------------------|
| 作用域 | 项目级（当前需求） | Agent 级（跨项目） |
| 持久化 | 文件持久化 | Agent 系统管理 |
| 可见性 | 团队可见（提交到 git） | 仅当前 Agent 可见 |
| 适用场景 | 项目特有的硬性规则 | 用户通用偏好 |

### MARK、_dev 与 Memory 的职责边界

- MARK（`CLAUDE.md`）只负责持久化**约束类信息**：必须、禁止、纠正规则、长期有效的项目硬约束。
- `_dev` 文件负责持久化**当前需求状态**：需求变更、阶段推进、代码实施、延后事项、技术决策。
- Memory 只负责持久化**跨任务稳定规则**：用户通用偏好，或已经被验证为跨项目/跨需求复用的流程经验。
- **MARK 不能替代 `_dev` 同步**：dirty-state 判定、回合收尾门禁、changelog 记录仍由 `_dev` 协议负责。
- **Memory 不能替代 `_dev` 当前状态**：不要把当前 feature 的阶段、待办、未补 changelog 等任务态信息写入 Agent 记忆。

**判断规则**：
- "这个项目不使用 autoResize" → MARK（项目特有）
- "我习惯用 4 空格缩进" → Memory（通用偏好）
- "changelog 必须记录根因" → MARK（项目规则）
- "回答用中文" → Memory（通用偏好）
- "本轮改了代码，必须同步 `changelog.md`" → `_dev` 协议（状态同步规则）
- "多轮对话需要先做最小恢复" → `_dev` 协议，可在 Memory 中保存为稳定流程经验

## MARK 的生命周期

```
触发 → 记录 → 生效 → [固化/废弃]
```

### 1. 触发条件

MARK 只在以下情况创建：
- 用户明确发出硬性规则（"以后不要..."、"必须..."、"禁止..."）
- 用户纠正了 Agent 的行为（"不是这样，应该..."）
- 发现重要约束需要持久化（如 Bug 根因揭示的规则）

### 2. 记录格式

```markdown
### MARK #N: [简短标题]
- 内容：[具体约束描述]
- 来源：[触发场景/对话轮次]
- 状态：生效 | 已固化 | 已废弃
- 关联：[相关的 Bug/DECISIONS 编号，可选]
```

### 3. 编号规则

- 从 #1 开始递增
- 废弃的 MARK 保留编号，不复用
- 新 MARK 使用当前最大编号 + 1

## 防遗漏机制

### 三层防护

```
Layer 1: CLAUDE.md 高频约束区（≤ 5 条）
         → 每次迭代前 Agent 必须回顾
         → 只放最容易被遗忘且影响最大的规则

Layer 2: SPEC.md 头部约束摘要
         → SPEC 顶部的 blockquote
         → 记录与需求强相关的核心约束

Layer 3: 回顾检查点协议（02_workflow.md）
         → 流程强制，不依赖 Agent 记忆
         → 定义"何时必须回顾什么"
```

### 高频约束区规范

CLAUDE.md 顶部的高频约束区：

```markdown
## ⚡ 高频约束（每次迭代必看）

1. `SPEC.md` 是第一准则，方向调整先改 `SPEC.md`
2. 本轮改了代码，必须同步 `changelog.md`
3. 所有 agent 文件归属当前 `_dev` 目录
4. 多轮对话先做最小恢复，再继续实施
5. dirty 的 `_dev` 产物不得跨轮悬空
```

**选入标准**：
- 被违反过至少一次的约束
- 违反后果严重的约束
- 容易在长对话中被遗忘的约束

## MARK 的固化与废弃

### 固化

当一个 MARK 被证明是长期有效的通用规则时，可以固化为：
- **Skill 规则**：提升到 sdd-workflow 的模块中
- **Memory**：只有在它已经被验证为跨项目、跨需求稳定复用的规则时，才转为 Agent Memory

固化判断：
- 约束类信息继续留在 `CLAUDE.md`
- 当前需求状态继续留在 `_dev` 文件
- 只有稳定的流程经验或用户通用偏好，才适合进入 Memory
- 当前 feature 的阶段、待办、dirty 文件、未补 `changelog.md` 等任务态信息**禁止**写入 Memory

固化后，MARK 状态改为"已固化"，并注明去向。

### 废弃

当一个 MARK 不再适用时：
- 状态改为"已废弃"
- 注明废弃原因
- 不删除（保留追溯）

```markdown
### MARK #5: 不使用 autoResize [已废弃]
- 内容：并发节点不使用 autoResize
- 来源：Bug 23 根因分析
- 状态：已废弃
- 废弃原因：需求变更，Phase 4 需要支持 autoResize
```

## Agent 回顾行为规范

### 回顾时机

参见 [02_workflow.md](02_workflow.md) 的回顾检查点协议。

### 回顾输出格式

```
📋 已回顾 CLAUDE.md（N 条 MARK），本次修改涉及：
- MARK #X：[标题]（[如何遵守]）
- MARK #Y：[标题]（[如何遵守]）
```

### 冲突处理

当 MARK 与当前需求冲突时：
1. 不要静默忽略 MARK
2. 向用户报告冲突
3. 由用户决定：修改 MARK 还是调整需求

---

## 反模式

❌ Agent 自己创建 MARK（必须是用户触发）
❌ MARK 超过 20 条（信息过载，失去防遗漏效果）
❌ 废弃的 MARK 直接删除（失去追溯能力）
❌ 高频约束区超过 5 条（应该只放最关键的）
❌ 回顾时只看不报告（必须输出确认信息）
❌ 遇到冲突时静默忽略 MARK
