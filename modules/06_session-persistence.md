# 06. 会话持久化

## 定位

`_dev/` 产出物是**面向交付的状态面板**（给团队和后续开发者看）。本模块定义的是**面向 Agent 上下文管理的工作记忆**（给 Agent 自己看），解决长对话、跨会话、多轮迭代中的信息丢失问题。

> ⚠️ **职责边界**：会话级文件不替代 `_dev/` 产出物。SPEC/PLAN/changelog 是交付物，findings/progress 是 Agent 的草稿纸。

---

## 会话级文件

| 文件 | 职责 | 写入时机 | 放置位置 |
|------|------|---------|---------|
| `findings.md` | 研究发现、源码笔记、调研结论 | 读源码/文档后有新发现时 | `_dev/` 内 |
| `progress.md` | 会话日志：本轮做了什么、遇到什么错误 | 每轮结束前 | `_dev/` 内 |

> ⚠️ 这两个文件是 Agent 工作记忆，不是交付物。可在 `.gitignore` 中排除，或标记为临时文件。`_dev/` 的产出物文件（SPEC/PLAN/changelog 等）仍然是交付物，必须提交。

### findings.md — 研究发现

**职责**：记录调研阶段的临时发现，供后续阶段引用。

**结构要求**：

```markdown
# 研究发现

## [日期/主题]

### 发现 1: [标题]
- 来源：[文件路径 / URL / 对话轮次]
- 内容：[一句话概括]
- 影响：[对哪个阶段/模块有影响]

### 发现 2: [标题]
...
```

**写入规则**：
- 只记录"后续可能用到但容易遗忘"的信息
- 每条发现必须有来源（可追溯）
- 不记录实施细节（那是 changelog 的职责）
- 不记录约束（那是 CLAUDE.md 的职责）

**反模式**：
- ❌ 把 SPEC 内容复制到 findings（信息冗余）
- ❌ 把临时发现写进 DECISIONS.md（职责错位，DECISIONS 只放架构决策）

---

### progress.md — 会话日志

**职责**：记录当前会话的工作轨迹，用于跨会话恢复。

**结构要求**：

```markdown
# 会话日志

## [日期] 会话 N

### 本轮目标
- [一句话描述本轮要做什么]

### 已完成
- [x] [动作] → 结果

### 遇到的问题
- [问题描述] → [如何解决 / 是否待解决]

### 下一步
- [下一步计划]
```

**写入规则**：
- 每轮结束前追加条目
- 记录"做了什么"而非"怎么做"（怎么做在 changelog）
- 错误和失败也要记录（防止重复踩坑）

**反模式**：
- ❌ 把 changelog 内容复制到 progress（信息冗余）
- ❌ 只记成功不记失败（失去防重复价值）

---

## 行为规则

### R1: 2-Action Rule

> 每完成 2 次读取/浏览/搜索操作后，立即将关键发现写入 `findings.md`。

**目的**：防止多模态信息（截图、PDF、浏览器内容）在上下文窗口中被遗忘。

**执行方式**：
```
读取文件 A → 读取文件 B → 立即写 findings.md → 继续读取
```

**适用场景**：
- 读源码理解模块结构
- 浏览设计稿/截图
- 搜索代码库查找模式
- 查看 API 文档

---

### R2: Read Before Decide

> 做重大决策前，先读取 `findings.md` 和 `_dev/` 产出物，刷新注意力窗口。

**目的**：确保决策基于完整信息，而非上下文窗口中残存的部分记忆。

**执行方式**：
```
即将做技术选型 / 修改共享模块 / 确定方案
→ 先读 findings.md（研究阶段发现了什么）
→ 再读 DECISIONS.md（已有决策是否相关）
→ 再读 SPEC.md（需求边界是否允许）
→ 然后才做决策
```

---

### R3: Write After Act

> 每完成一个阶段或重要动作后，立即更新 `progress.md` 和对应 `_dev/` 产出物。

**目的**：将工作状态从易失的上下文窗口转移到持久化的文件系统。

**执行方式**：
```
完成阶段 N
→ 更新 progress.md（本轮做了什么）
→ 更新 PLAN.md（阶段状态）
→ 更新 changelog.md（代码变更记录）
→ 更新 findings.md（如有新发现）
```

---

### R4: Read vs Write 决策矩阵

| 场景 | 动作 | 原因 |
|------|------|------|
| 刚写入文件 | 不读 | 内容仍在上下文 |
| 读了源码/截图/PDF | 立即写 `findings.md` | 多模态信息易丢失 |
| 浏览器返回数据 | 写 `findings.md` | 截图不持久 |
| 开始新阶段 | 读 `findings.md` + `_dev/` 产出物 | 刷新注意力 |
| 遇到错误 | 读 `progress.md` 最近条目 | 了解之前是否遇到过 |
| 跨会话恢复 | 读全部会话级 + `_dev/` 文件 | 完整恢复状态 |

---

## 跨会话恢复协议

### 触发条件

以下任一满足时，必须执行跨会话恢复：

- 新会话开始（之前的会话已结束）
- `/clear` 后重新进入需求
- 重新进入已有 `_dev/` 目录继续实施
- 上一轮已改代码，但未显式确认 `_dev` 已同步

### 恢复步骤

```
Step 1: 检查代码变更
   → git diff --stat（查看自上次以来的代码改动）
   → git log --oneline -5（查看最近提交）

Step 2: 读取会话级文件
   → progress.md（上次会话做到哪一步）
   → findings.md（研究阶段发现了什么）

Step 3: 读取 _dev/ 产出物（最小恢复集合）
   → SPEC.md（需求是什么）
   → CLAUDE.md（有哪些约束）
   → PLAN.md（当前在哪个阶段）
   → changelog.md 最近条目（上次改了什么）
   → 必要时 TODO.md（有哪些待办）

Step 4: 对比与修正
   → 代码变更是否已反映在 changelog 中？
   → 阶段状态是否与 PLAN.md 一致？
   → 如有偏差，先同步 _dev/ 产出物，再继续工作
```

### 恢复输出格式

```
📋 跨会话恢复完成：
- 代码变更：[git diff --stat 摘要]
- 上次进度：[progress.md 最近条目摘要]
- 当前阶段：PLAN.md Phase [N] [状态]
- 未同步项：[列出 dirty 的 _dev/ 文件，或"无"]
```

## 与 _dev/ 产出物的关系

| 信息类型 | 写入位置 | 理由 |
|----------|---------|------|
| 需求规格 | `SPEC.md` | 交付物，团队可见 |
| 架构决策 | `DECISIONS.md` | 交付物，团队可见 |
| 代码变更记录 | `changelog.md` | 交付物，团队可见 |
| 用户硬约束 | `CLAUDE.md` | 交付物，团队可见 |
| 阶段规划 | `PLAN.md` | 交付物，团队可见 |
| 待办事项 | `TODO.md` | 交付物，团队可见 |
| 源码阅读笔记 | `findings.md` | 会话级，Agent 工作记忆 |
| 调研发现 | `findings.md` | 会话级，Agent 工作记忆 |
| 会话工作轨迹 | `progress.md` | 会话级，Agent 工作记忆 |
| 临时错误记录 | `progress.md` | 会话级，Agent 工作记忆 |

> ⚠️ **原则**：如果信息需要团队后续开发者看到，写入 `_dev/` 产出物；如果只是 Agent 当前工作需要的临时记忆，写入会话级文件。

## 3-Strike Error Protocol

遇到错误时的处理策略：

```
ATTEMPT 1: 诊断 & 修复
  → 仔细阅读错误信息
  → 定位根因
  → 应用针对性修复
  → 记录到 progress.md

ATTEMPT 2: 替代方案
  → 同样的错误？换一种方法
  → 不同工具？不同库？
  → 记录到 progress.md（标注"尝试 2"）
  → 绝不重复完全相同的失败动作

ATTEMPT 3: 更广泛地重新思考
  → 质疑假设
  → 搜索解决方案
  → 考虑更新 PLAN.md
  → 记录到 progress.md（标注"尝试 3"）

3 次失败后：升级到用户
  → 说明已尝试的方案
  → 分享具体错误
  → 请求指导
```

> ⚠️ **铁律**：`if action_failed: next_action != same_action`。记录尝试过的方法，变换策略。

## 何时创建会话级文件

| 场景 | 是否创建 | 说明 |
|------|---------|------|
| 中大需求（完整 5 阶段流程） | ✅ 创建 | 调研阶段有大量发现需要记录 |
| 小需求（简化流程） | ❌ 不创建 | 上下文窗口足够覆盖 |
| 热修复（< 10 行） | ❌ 不创建 | 无需持久化 |
| 多轮迭代（> 5 轮对话） | ✅ 创建 | 需要跨轮恢复 |
| 跨会话继续 | ✅ 创建 | 必须有 progress.md 才能恢复 |

> ⚠️ **最小必要**：不为了"完整"而创建会话级文件。小需求用上下文窗口 + Agent task_list 即可。

---

## 反模式

- ❌ 把 SPEC/PLAN/changelog 内容复制到 findings.md（信息冗余）
- ❌ 把临时发现写进 DECISIONS.md（职责错位）
- ❌ 把会话日志写进 changelog.md（changelog 是代码变更记录，不是会话轨迹）
- ❌ 创建了 findings.md 但不更新（失去价值）
- ❌ 跨会话恢复时只读 `_dev/` 产出物，不读 progress.md/findings.md（丢失工作轨迹）
- ❌ 重复尝试相同的失败动作（违反 3-Strike Protocol）
